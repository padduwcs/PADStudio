# Project intake

## Use when

The project intent, audience, desired outcome, constraints, or available material are not yet dependable enough to plan work.

## Method

1. Read existing project state before asking anything.
2. Treat a short request as sufficient to begin. Inspect supplied material before deciding the video's form, length, narration or emphasis. Distinguish a representative sample from a complete preview.
3. Extract what is known from the request and evidence; label assumptions explicitly. When a consequential choice would leave a salient supplied source unused, record the choice and why it still serves the user's goal. Do not assume that available material must all be used.
4. Ask only questions whose answers can materially change the direction or scope and cannot be resolved responsibly from the request and evidence. Do not make the user brainstorm a production plan.
5. Record the result as a `project.brief` artifact using contract version `1.0`: `purpose`, `audience`, `desiredOutcome`, and the arrays `constraints`, `knownFacts`, `assumptions`, `openQuestions`.
6. Keep facts, assumptions, and unresolved questions separate. Do not fill uncertainty with invented certainty.

The exact contract and revision rules are defined in `docs/build/CREATIVE-DIRECTION-SPEC.md`.

## Standard

The brief is useful when another Agent can explain what success means, what must not change, and what remains uncertain without replaying the conversation.
